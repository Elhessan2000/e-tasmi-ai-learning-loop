## 💡 Project Overview

**e-Tasmi** is an online *tasmi'* platform: learners recite the Qur'an to a qualified instructor, either in live sessions or by uploading a recording, and receive an evaluation.

**The problem.** A score alone does not tell a learner what to practise next, and instructors spend a long time listening for every missed or changed word.

**The challenge contribution.** e-Tasmi already had accounts, sessions, recitation upload, instructor scoring, and a Qur'an library before the challenge. The challenge adds an **AI-assisted learning loop**. AI prepares a structured analysis of each recitation, the instructor verifies it, and the verified findings become the learner's next practice focus.

| 📐 Deterministic diff | 🤖 Advisory AI | 🛂 Instructor gate |
|---|---|---|
| Qur'an text is never generated by a model. Word differences are computed in Java against trusted Hafs text from Quranpedia. | GPT-6.1 Sol explains findings that already exist. It does not invent verses. | Findings stay `PENDING` until an instructor verifies them. Nothing reaches the learner before that. |

## 🤖 AI Learning Loop

<p align="center">
  <strong>🎙️ Recite → 🔍 AI Analysis → 🛂 Instructor Verification → 💬 Personalized Feedback → 🔁 Practice &amp; Improve → 🎙️ Recite Again</strong>
</p>

| Stage | What happens |
|---|---|
| 🎙️ **Recite** | The student records or uploads a recitation for an enrolled session and passage. |
| 🔍 **AI Analysis** | ElevenLabs Scribe v2 transcribes the audio. A Java engine compares the transcript word by word with the trusted Hafs passage and records each finding: **missing**, **incorrect**, or **extra** words, **passage mismatch**, advisory **pronunciation observations**, and other notes. GPT-6.1 Sol then explains the findings and drafts a suggested score and feedback. |
| 🛂 **Instructor Verification** | The instructor listens, then **accepts, edits, rejects, or adds** findings and sets the final score and feedback. Publication is blocked while any finding is still pending. |
| 💬 **Personalized Feedback** | The student sees the published score, the instructor's feedback, and a **Verified Learning Focus** built only from accepted, edited, or instructor-added findings. |
| 🔁 **Practice &amp; Improve** | **Practice Again** starts a linked attempt on the same enrollment. Student Progress shows the latest verified focus, a comparison with the previous published attempt, and the published history. |

> [!IMPORTANT]
> **AI assists; the instructor decides.** The final evaluation is always the instructor's. The instructor gate is enforced on the server: a pending finding cannot reach the learner, and an unverified analysis cannot be published.

> [!NOTE]
> A transcript cannot prove tajweed or articulation errors, so pronunciation observations are advisory and marked for the instructor's acoustic review. If the trusted passage cannot be loaded, the comparison is withheld and no Qur'an text is stored.

## 🚀 Evaluation & Getting Started

**Evaluate the live system (recommended)**

1. Open **[e-tasmi.com](https://e-tasmi.com)** and sign in as the **student**. Submit a recitation for an enrolled session.
2. Sign in as the **instructor**, open the evaluation, run the AI analysis, and review each finding. Then set the score and feedback and publish.
3. Return as the **student** to see the result and the Verified Learning Focus. Start **Practice Again**, then open **Student Progress**.

**Watch the demo:** [Live Demo.mp4](docs/submission/demo/Live%20Demo.mp4) · [demo script](docs/submission/demo/README.md)

**Run the local challenge copy**

```bash
cd e-Tasmi
cp .env.example .env        # add your own keys
docker compose up -d --build
# app: http://localhost:8084   (Compose project: etasmi-ai-challenge)
```

Full setup, including Caddy on port 8444: [docs/development/installation.md](docs/development/installation.md). Do not point this stack at a production database.

## ✅ Validation, Privacy & Limits

- **Recorded on 2–3 Oct 2026:** 31 functional cases and 32 comparison checks, all passed ([validation](docs/challenge/validation.md)). Student Progress is not part of that count. It was checked against the source on 6 Oct 2026, and its earlier browser session was not repeated in the documentation pass.
- API keys stay in the ignored `.env` file. In the tested flows, ownership checks return the same 404 for a missing recitation and for one the student does not own. This is not a claim that the system is fully secure.
- Practice attempts still count in the existing progress average. Behaviour screenshots are not in `docs/challenge/challenge-evidence/` yet.
- Vendor prices and licences that are not copied from a provider page are unverified. Check current pricing on each provider's official pricing page at submission time.
