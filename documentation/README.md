# e-Tasmi AI Learning Loop — Documentation

This directory contains the official documentation for **e-Tasmi AI Learning Loop**, submitted to the **AI Challenge in Service of Islamic Content 2026**.

The documentation clearly separates the **pre-challenge baseline** from work carried out during the official challenge period. This ensures that existing functionality is not presented as challenge-period development, while all new contributions are documented with their implementation and evidence.

## 📌 Documentation Structure

### 1. Baseline Documentation

[baseline/](baseline/README.md) documents the system as it existed **before the official challenge development period**.

It records:

- Existing system functionality
- Existing AI capabilities
- Technical environment
- Baseline Git commit and repository state
- Existing architecture and database structure
- Third-party services and dependencies
- Data privacy and responsible-use considerations
- Supporting baseline evidence

This section establishes the documented starting point for the challenge.

### 2. Challenge Development

[challenge/](challenge/README.md) records all work performed **during the official challenge development period**.

It includes:

- Development plan
- Implementation progress
- Contribution records
- Validation and testing
- Challenge-period evidence

Planned features are clearly identified as **planned** until they are actually implemented and documented.

### 3. Setup & Installation

[setup/](setup/README.md) provides instructions for running the isolated local challenge environment.

It covers:

- Required software
- Environment configuration
- Database setup
- Docker configuration
- Application startup
- Local development workflow

### 4. Final Submission

[final/](final/README.md) contains the materials prepared for the final challenge submission.

This includes:

- Final report
- Submission checklist
- Demo documentation
- Supporting submission materials

All final documents are based on implemented and documented work and avoid unsupported claims.

## 🔎 Documentation Principle

> **Document what existed. Build what is new. Evidence what was implemented.**

The documentation maintains a clear distinction between:

**Existing System → Challenge Contribution → Validation → Final Submission**

This structure provides a transparent record of the project's development throughout the challenge.
